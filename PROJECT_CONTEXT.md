## Восстановление пароля — 23 октября 2026

- Подтверждённая причина: форма forgot-password была таймером без API, resend только возвращал форму; backend recovery route отсутствовал. На опубликованном frontend это воспроизведено с блокировкой всех POST: успех при 0 попыток auth POST. 401 login не связан с подтверждённой причиной.
- Добавлен POST /api/auth/forgot-password → существующая PasswordSetupToken (SHA-256, случайные 32 байта, 1 час) → awaited Resend. Публичные статус/JSON одинаковы для существующего/неизвестного email и отказа провайдера. Безопасные структурированные логи, отзыв нового токена при отказе отправки, отдельный IP-limiter. Форма/resend вызывают API; CSS и соседние кнопки не менялись.
- Проверки: 10 HTTP-тестов с mocked Prisma/Resend; 2 новых PG-сценария и 5 существующих auth-тестов на временной отдельной PostgreSQL; 4 desktop/mobile UI-теста с перехватом API; полный server npm test (33 теста до добавления PG-suite), backend/frontend сборки, TypeScript и ESLint страницы прошли. Однократность проверена конкурентными запросами к настоящей тестовой БД. Скриншоты успеха просмотрены.
- Реальные письма не отправлялись, пароли существующих пользователей не менялись, production не менялся. Локальный server/.env без RESEND_API_KEY/EMAIL_FROM; это не подтверждает runtime production. Доступа к production-логам/env и панели Resend нет, доставка/домен/права ключа не проверены. Перед реальной отправкой согласовать тестовый адрес.
- Подробности, команды и ограничения: docs/password-recovery.md. Следующий шаг: отдельно проверить production runtime-конфигурацию и доставку на согласованный адрес; затем только по разрешению публиковать.
- Разрешённая пользователем проверка реальной доставки: адрес владельца найден в локальной PostgreSQL (только чтение, пароль не менялся). Отправку не выполняли: локальный backend не запущен, RESEND_API_KEY и EMAIL_FROM отсутствуют и в server/.env, и в окружении сессии; нет доступа к панели Resend. Для продолжения нужны ключ, подтверждённый отправитель и доступ к статусу письма. Не вызывать recovery API ради формального success при отсутствующей конфигурации. Production не менялся; адрес и токены здесь не сохраняются.
